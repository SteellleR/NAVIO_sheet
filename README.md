# NAVIO Sheet - полная техническая передача

> Если ты читаешь это после меня - не пугайся. Проект уже разложен по файлам,
> основные сценарии покрыты локальными проверками, а код не нужно копировать в
> Apps Script руками. Ниже я собрал всё, что сам хотел бы получить при передаче:
> что здесь вообще происходит, где что лежит, как безопасно менять код, как его
> тестировать, выкатывать и откатывать, где смотреть ошибки и какие у Google
> есть лимиты.

## Самое важное за одну минуту

Это связанный с Google Таблицей проект Apps Script. Он обслуживает три рабочих
листа:

- `ПАО`;
- `Такси`;
- `Шаттл`.

Любой из них можно временно исключить через `NAVIO → Управление листами`, не
меняя код и не удаляя данные. Хотя бы один рабочий лист должен оставаться
включённым.

Проект делает пять больших вещей:

1. Создаёт служебные ссылки `Добавить лог` по дате события и номеру ВАТС.
2. Один раз переносит дату события в `Дата проверки лога` и учитывает её
   исправление.
3. Следит за настоящими ссылками Logviewer, статусом `заполнен` и выбором
   `Сегодня`.
4. Каскадно синхронизирует шторки телеоператоров и ВАТС со справочниками.
5. Собирает обратимый отчёт об ошибках на листе `Нарушители`.

## Окружения и безопасная привязка

Для разработки лучше держать отдельные тестовую и основную таблицы, у каждой
будет свой связанный проект Apps Script. Конкретные ссылки и идентификаторы я в
README не храню: их нужно брать из актуальной таблицы и настроек её скрипта.

### Не перепутай два вида ID

- **Spreadsheet ID** берётся из URL таблицы между `/d/` и `/edit`.
- **Script ID** находится в редакторе Apps Script:
  `Настройки проекта → Идентификаторы → Идентификатор скрипта`.

`clasp` принимает именно **Script ID**. Если положить туда Spreadsheet ID,
ничего хорошего не получится.

Файл `.clasp.json` специально добавлен в `.gitignore`: он определяет, в какой
удалённый Apps Script уйдёт следующая команда `push`. Перед каждой публикацией я
обязательно открываю его и глазами проверяю `scriptId`.

Безопасное состояние по умолчанию - локальная `.clasp.json` привязана к тесту.
После публикации на основу её стоит сразу вернуть на тестовый проект.

## Как устроена таблица

### Рабочие листы

Имена должны совпадать **буква в букву**:

- `ПАО`;
- `Такси`;
- `Шаттл`.

Заголовок рабочей таблицы находится в строке `1`, данные начинаются со строки
`2`. Код ищет столбцы по заголовкам, а не по жёстким номерам. Поэтому столбцы
можно переставлять местами, но нельзя бесконтрольно переименовывать.

Обязательные заголовки:

| Заголовок | Для чего нужен |
| --- | --- |
| `Дата` | Дата события, основа для ссылки Logviewer и окна в 30 дней. |
| `ВАТС` | Номер машины для параметра `rovers_regexp`. |
| `Телеоператор` | Владелец строки и ключ для отчёта `Нарушители`. |
| `Logviewer` | Служебная или настоящая ссылка на лог. |
| `Дата проверки лога` | Зафиксированная дата события, ручное обновление через `Сегодня` или `заполнен`. |

Каждый рабочий диапазон должен оставаться **нативной таблицей Google Sheets**,
а не просто раскрашенным диапазоном. Проект читает метаданные нативных таблиц и
через `updateTable` меняет их dropdown-столбцы.

### Активные и приостановленные листы

`ПАО`, `Такси` и `Шаттл` - разрешённый набор рабочих листов, но не обязательно
все они отслеживаются одновременно. Текущий выбор хранится в `Document
Properties` конкретной таблицы. Если настройка ещё не сохранялась, активны все
три листа.

Приостановленный лист:

- не сканируется полным проходом `Нарушителей`;
- не участвует в синхронизации dropdown телеоператоров и ВАТС;
- не получает автоматические даты и `Добавить лог`;
- не обрабатывается профильной логикой обычного `onEdit`;
- остаётся в файле со всеми данными без изменений.

Сам простой `onEdit` всё равно вызывается Google для таблицы целиком, но для
приостановленного листа обработчики делают только быструю проверку настройки и
сразу завершаются. Основная нагрузка - чтение строк, RichText, форматирование и
отчёт - не выполняется.

После отключения листа полный отчёт пересобирается сразу, поэтому его старые
адреса исчезают из `Нарушителей`. После повторного включения проект обновляет на
активных листах справочники, даты, статусы и служебные ссылки, затем заново
строит отчёт.

### Лист `Телеоператоры`

Справочник начинается с заголовка в строке `1`, данные - со строки `2`.

Для логина допустим один из заголовков:

- `Логин`;
- `Телеоператор`;
- `Телеоператоры`.

Необязательный столбец `ФИО` можно использовать для читаемого имени. Ключом
всегда остаётся логин.

Что делает код:

- убирает пустые строки;
- устраняет одинаковые логины без учёта регистра и лишних пробелов;
- не даёт одному логину соответствовать разным ФИО;
- полностью заменяет варианты в шторках трёх рабочих таблиц;
- поэтому работает и каскадное добавление, и каскадное удаление;
- после изменения справочника полностью пересобирает `Нарушителей`.

### Лист `ВАТС`

Лист необязательный: если его нет, `installProject()` пропускает синхронизацию
ВАТС и продолжает установку.

Если лист есть, ожидаются заголовки:

| Заголовок | Значение |
| --- | --- |
| `Название` | Старое или человекочитаемое название. |
| `Номер ВАТС` | Значение, которое должно попасть в рабочие шторки. |
| `Статус` | Только `Active` или `Inactive`. |

В рабочие dropdown-списки попадают только уникальные номера со статусом
`Active`. У активной строки номер обязателен. Неизвестный статус останавливает
синхронизацию с понятной ошибкой и номером строки.

### Лист `Нарушители`

Это не ручной справочник, а полностью производный отчёт.

- Имя листа: `Нарушители`.
- Имя нативной таблицы: `Нарушители`.
- Заголовки: строка `5`.
- Данные: с `A6`.
- Нативная таблица должна начинаться с `A5` и занимать `A:C`.

Точные заголовки:

| Столбец | Заголовок |
| --- | --- |
| A | `Телеоператор` |
| B | `Дата не обновлена` |
| C | `Адрес ошибки (Не обновлена)` + перенос строки + `Лист / строка` |

Код сам расширяет нативную таблицу, если сотрудников станет больше. Вручную
ставить туда смайлики или поддерживать список адресов не нужно: следующий полный
проход всё равно восстановит производное состояние из рабочих листов.

## Бизнес-логика по блокам

### 1. Служебная ссылка `Добавить лог`

Когда в рабочей строке есть корректная `Дата` и распознаваемый `ВАТС`, код
строит локализованную формулу `HYPERLINK` с подписью `Добавить лог`.

В URL передаются:

- нормализованный номер ВАТС через `rovers_regexp`;
- одна и та же дата как начало и конец `date_range`.

Пример логики нормализации:

```text
КС2-021 → kc2-021
КС2 21  → kc2-021
KC2-21  → kc2-021
SH-2    → sh-002
```

Служебная ссылка проверяется при любом ручном изменении строки. Поэтому порядок
заполнения кейса не важен: как только в строке одновременно есть корректная
дата и распознаваемый ВАТС, пропущенный `Добавить лог` будет восстановлен. Если
обязательных данных больше нет, удаляется только служебная ссылка.

Настоящую ссылку, произвольный текст или чужую формулу код не перезаписывает.

### 2. Что считается настоящим логом

Настоящей считается ссылка, содержащая префикс:

```text
https://logviewer.df.sbauto.tech/logs/
```

Проверяются все представления ячейки:

- обычное значение;
- отображаемый текст;
- формула;
- прямая RichText-ссылка;
- ссылки отдельных RichText-сегментов.

Это сделано специально, потому что пользователи вставляют ссылки разными
способами, а Google Sheets хранит их тоже по-разному.

### 3. Динамический статус `заполнен`

Если в `Logviewer` появляется настоящая `/logs/`-ссылка, код заменяет пустоту
или календарную контрольную дату на `заполнен`.

Если настоящую ссылку удалить, код снимает `заполнен` и восстанавливает текущую
дату события из первого столбца. Произвольный пользовательский текст код не
перезаписывает.

То есть `заполнен` - не одноразовая метка навсегда, а состояние, которое следует
за фактическим наличием настоящего лога.

### 4. Значение `Сегодня`

Во всех трёх нативных dropdown-столбцах `Дата проверки лога` должны быть два
служебных варианта:

```text
Сегодня
заполнен
```

Когда пользователь выбирает `Сегодня`, простой `onEdit` сразу заменяет его на
фиксированное значение даты `дд.мм.гггг` в часовом поясе таблицы
`Europe/Moscow`.

Это не формула `TODAY()`. Поэтому завтра значение не изменится само и честно
покажет день проверки. Значение передаётся в Sheets сразу как `дд.мм.гггг`:
у нативного типизированного столбца иногда пропадает числовой формат и вместо
даты появляется внутренний serial number вроде `46272`. Google может сохранить
переданное значение как нативную дату - это нормально. Код умеет разобрать оба
варианта, а повторная синхронизация чинит потерянное отображение.

### 5. Автозаполнение от даты события

Когда пользователь вводит дату события в первом столбце, код один раз копирует
её в `Дата проверки лога` как фиксированное значение `дд.мм.гггг`.
Формула `TODAY()` не используется, поэтому дата сама не «клацает» каждый день.

Если пользователь исправляет одиночную ячейку даты события и контрольная дата
всё ещё равна прежней дате события, код переносит исправление. Если контрольную
дату уже обновили через `Сегодня` или там стоит `заполнен`, исправление даты
события её не перезапишет.

При установке функция `syncLogCheckDatesFromEvents()` порциями по 500 строк
заполняет пустые контрольные даты и нормализует уже существующие календарные
значения. В том числе она чинит старые serial numbers. `заполнен` и произвольный
пользовательский текст сохраняются. Сравнение идёт по отображаемому значению,
поэтому уже исправные даты повторно не записываются при каждом запуске.

### 6. Условное форматирование

Проект управляет одним своим правилом в столбце `Дата проверки лога`:

| Состояние | Фон | Цвет текста |
| --- | --- | --- |
| `Дата проверки лога = заполнен` | `#d9ecc0` | `#35714e` |

Остальные пользовательские правила листа должны сохраняться. Код узнаёт свои
старые формулы, при установке удаляет устаревшее красное правило и при
необходимости создаёт актуальное зелёное.

### 7. Правила `Нарушителей`

Проверяются только строки, дата события которых попадает в окно от сегодняшнего
дня до 30 календарных дней назад. Будущие и более старые строки игнорируются.

#### `Дата не обновлена`

Нарушение есть, если:

- в `Дата проверки лога` стоит настоящая дата;
- этой дате четыре календарных дня или больше.

Событие от 20.04 впервые считается нарушением 24.04: это пятый календарный день,
если считать сам день события первым.

Значение `заполнен` нарушением не считается.

#### Как пишется результат

Для телеоператора ставится один `😡`. Адреса группируются по логину и
объединяются через `; `:

```text
ПАО / 987; Такси / 1852; Такси / 1876; Шаттл / 76
```

Ошибок может быть сколько угодно. После исправления исходной строки конкретный
адрес исчезает. Если других ошибок этой категории не осталось, исчезает и
смайлик.

Удалённый из справочника телеоператор исчезает из отчёта после полной
синхронизации.

## Как события проходят через проект

### Простой `onOpen(e)`

При открытии таблицы:

1. Добавляет меню `NAVIO`.
2. Проверяет зелёное правило `заполнен` и удаляет устаревшее красное правило,
   если оно осталось от старой версии.

Полного сканирования `Нарушителей` на открытии больше нет - это было слишком
дорого и создавало ощущение, что таблица долго просыпается.

Если меню не появилось после загрузки нового кода, сначала полностью обнови
страницу. Если и это не помогло, открой `Расширения → Apps Script`, выбери
`installProject` и запусти вручную.

### Простой `onEdit(e)`

На рабочих листах порядок принципиален:

1. Дата события переносится в контрольную дату, а `Сегодня` превращается в
   настоящую дату.
2. Обновляется служебная ссылка, `заполнен` или восстановленная дата события.
3. `Нарушители` получают итоговое состояние изменённых строк.

Этот обработчик не сканирует всю таблицу. Он работает только с диапазоном,
которого коснулось редактирование.

### Установочный `onEdit`

Функция `handleReferenceSheetsEdit` следит за листами-справочниками:

- `Телеоператоры`;
- `ВАТС`.

Она требует installable-триггер, потому что синхронизация нативных dropdown
использует Sheets API и OAuth-токен.

Старые имена `handleTeleoperatorsEdit` и `handleTeleoperatorsChange` оставлены
как переходные обёртки. После нормального `installProject()` старые триггеры
удаляются, но код не ломается в момент обновления между версиями.

### Установочный `onChange`

`handleReferenceSheetsChange` реагирует на вставку и удаление строк/столбцов и
структурные события `OTHER`. Он пересинхронизирует справочники и делает полный
пересчёт отчёта.

### Периодический триггер

`handleViolatorsPeriodicSync` выполняет полный контрольный проход каждые
10 минут. Он нужен не для обычных ручных правок, а как страховка:

- наступил пятый день, но никто строку не редактировал;
- данные изменились способом, который не вызвал обычный `onEdit`;
- была массовая или структурная операция;
- инкрементальный проход пропустился из-за временной блокировки;
- отчёт нужно привести к единому состоянию после внешних изменений.

Старое имя `handleViolatorsDailySync` оставлено для обратной совместимости, но
новая установка создаёт именно десятиминутный триггер.

## Производительность и что именно оптимизировано

Раньше любое релевантное редактирование могло запускать полный проход по трём
листам. Чем больше росла таблица, тем хуже это ощущалось.

Сейчас есть два режима.

### Инкрементальный проход

При обычном редактировании код:

1. Читает только изменённые строки рабочего листа.
2. Удаляет прежние адреса этих строк из текущего отчёта.
3. Заново классифицирует только эти строки.
4. Записывает обновлённые B:C, только если состояние реально изменилось.

Смена телеоператора тоже обратима: адрес сначала удаляется у всех операторов, а
потом при необходимости добавляется текущему. Поэтому многострочная вставка и
замена логина не оставляют старые хвосты.

### Полный проход

Полный проход:

1. Один раз получает метаданные нативных таблиц через Sheets API.
2. Берёт фактические границы таблиц, а не весь запас строк листа.
3. Читает каждый рабочий лист одним непрерывным диапазоном вместо четырёх
   отдельных запросов к столбцам.
4. В памяти классифицирует строки.
5. Одной записью пересобирает A:C листа `Нарушители`.
6. Расширяет нативную таблицу только если сотрудников стало больше её ёмкости.

### Реальный контрольный замер

На тестовой таблице 27 августа 2026 года полный проход показал:

```json
{
  "mode": "full",
  "durationMs": 26954,
  "rowsScanned": 6609,
  "sheetsScanned": 3,
  "operators": 15,
  "staleRows": 2
}
```

То есть 6 609 строк были обработаны примерно за 27 секунд. Это нормальный
результат, но интервал в 10 минут для обычного личного аккаунта уже требует
контроля квоты: 144 запуска × 26,954 секунды ≈ 64,7 минуты в сутки только на
полные проходы.

### Где смотреть замеры

Каждый полный и инкрементальный проход пишет запись:

```text
[Violators performance] {...}
```

В объекте есть:

- `mode`: `full` или `incremental`;
- `durationMs`;
- `finishedAt`;
- `rowsScanned`;
- `sheetsScanned`;
- `operators`;
- для полного прохода - количество строк с неактуальной датой.

Смотреть можно в редакторе Apps Script:

```text
Выполнения → нужный запуск → Журналы
```

Последний успешный полный замер сохраняется в `DocumentProperties`. Его можно
получить ручной функцией:

```javascript
getLastViolatorsFullSyncMetrics()
```

### Когда менять интервал

Интервал находится здесь:

```javascript
APP_CONFIG_.violators.fullSyncIntervalMinutes
```

Сейчас это `10`. Если таблица продолжит расти или аккаунт окажется обычным
consumer-аккаунтом с лимитом 90 минут, разумный первый шаг - перейти на `15`:

```text
96 запусков × 26,954 секунды ≈ 43,1 минуты в сутки
```

После изменения интервала нужно снова запустить `installProject()`, иначе уже
созданный триггер останется на старом расписании.

## Меню `NAVIO`

Меню появляется в Google Таблице после `onOpen` и содержит три команды.

### `Установить или обновить проект`

Запускает `installProject()`:

1. Сохраняет ID связанной таблицы для фоновых запусков.
2. Удаляет только триггеры этого проекта, включая старые имена.
3. Для активных листов восстанавливает форматирование и dropdown даты.
4. Заполняет и нормализует контрольные даты.
5. Синхронизирует списки телеоператоров и ВАТС.
6. Восстанавливает Logviewer-ссылки и динамические статусы.
7. Полностью пересобирает `Нарушителей` только по активным листам.
8. После массовых изменений создаёт installable `onEdit` и `onChange`.
9. Создаёт полный проход раз в 10 минут.
10. Показывает toast `Проект установлен и синхронизирован`.

Команда безопасно переустанавливает только собственные триггеры. Чужие
триггеры проекта не удаляются.

### `Полный пересчёт нарушителей`

Вручную запускает `syncViolators()`. Полезно после массовых изменений или для
диагностики, но нажимать постоянно не нужно - есть автоматический таймер.

### `Управление листами`

Открывает HTML-окно с переключателями `ПАО`, `Такси` и `Шаттл`. Для каждого
листа видно состояние `Отслеживается` или `Приостановлен`.

После нажатия `Сохранить`:

1. Проверяется, что включён хотя бы один лист.
2. Выбор сохраняется для текущей таблицы.
3. Если лист включили обратно, на него возвращается актуальная служебная логика.
4. `Нарушители` сразу пересобираются без отключённых листов.

Повторный деплой и открытие редактора Apps Script для этого не нужны.

### `Документация`

Вложенное меню открывает два самостоятельных режима справки прямо в таблице:

- `Для пользователя` - короткая инструкция по рабочим листам, датам, Logviewer
  и «Нарушителям», а расширенные действия с листами, структурой и скрытым
  справочником вынесены в отдельную зону для операторов таблицы;
- `Для разработчика` - два маршрута сопровождения: пошаговая работа через
  обычный ИИ-чат и подробная техническая карта для разработчика, который сам
  работает с JavaScript, HTML, `clasp` и Apps Script.

Оба режима используют один адаптивный HTML-интерфейс в фирменном стиле Navio:
боковую навигацию, раскрывающиеся ответы, индикатор чтения и адаптацию под размер
окна. Глобальной кнопки «Раскрыть всё» нет: длинные разделы открываются точечно.
Поиск оставлен только в подробной разработческой справке; его иконка встроена
как SVG и выровнена относительно текста. Внешние библиотеки интерфейсу не нужны.
Фоновая фотография берётся с публичного медиахранилища корпоративного сайта;
при её недоступности текст и навигация остаются рабочими на чёрном фоне.

В начале разработческой справки есть блок `Для ИИ` с двумя независимыми
промптами:

- HTML-промпт работает только с `DocumentationDialog.html` и
  `SheetTrackingDialog.html`, не вмешиваясь в backend;
- backend-промпт работает только с `.gs` и `appsscript.json`, не переписывая
  HTML-интерфейсы.

Оба промпта рассчитаны на обычную чат-модель и человека без опыта разработки.
Они требуют вести пользователя по интерфейсу Apps Script пошагово, запрашивать
только нужные файлы и скриншоты, возвращать готовый код, проводить проверку и не
публиковать непроверенную правку сразу на основной таблице. Над карточками есть
простое объяснение выбора: HTML-промпт нужен для документации и интерфейсов,
backend-промпт - для функций и принципа работы скриптов.

Перед началом реализации обе инструкции требуют сначала собрать контекст,
показать пользователю готовый план и отдельно спросить `Начинаем?`. До явного
согласия модель не должна выдавать код или вести человека по первому шагу
внедрения. Если требования меняются, план собирается заново.

Встроенные версии содержат самостоятельный контекст, чтобы обычная модель не
вытягивала устройство проекта десятками наводящих вопросов. HTML-промпт знает
назначение таблицы, структуру двух режимов документации, пользовательские
гарантии, UI-механику, фирменную визуальную систему, адаптивность и границы с
backend. Backend-промпт содержит карту всех `.gs`-файлов, структуру нативных
таблиц, жизненный цикл строки, события и триггеры, правила дат, Logviewer,
справочников и «Нарушителей», PropertiesService, блокировки, scopes, квоты,
локальные проверки, GitHub и безопасную публикацию.

Промпт можно скопировать или скачать как UTF-8 TXT. TXT - запасной путь для
чатов, которые не принимают большой текст обычным сообщением. Кнопка
`Редактировать промпт` сохраняет новую версию именно для текущей таблицы;
`Вернуть встроенный` удаляет переопределение.

Предупреждение над промптами выделено красной полосой без дублирующей иконки и напоминает о трёх вещах:
большой текст можно передать как TXT, существенные изменения нужно отражать в
документации и промптах, а разработку сначала следует обкатывать на копии
таблицы и только после проверки переносить на основу.

Длинные пользовательские версии промптов хранятся в `Document Properties`
частями по 2400 символов под ключами
`documentation_prompt_html_v1_*` и
`documentation_prompt_backend_v1_*`. Запись защищена `DocumentLock`, пустой
промпт не принимается, общий размер ограничен 40 000 символами. Встроенный текст
остаётся запасным вариантом и не меняется при редактировании. Каждый промпт
обязывает ИИ после существенной работы сформировать актуальную полную версию,
объяснить важность обновления и провести пользователя до её сохранения через
интерфейс документации. Существенными считаются новые/удалённые функции,
изменение бизнес-логики, структуры таблицы, событий, разрешений или процесса
публикации. Опечатки, косметика и внутренний рефакторинг без изменения контракта
не создают обязательного документооборота. После серьёзной backend-правки модель
должна отдельно направить пользователя к HTML-промпту, если поменялось видимое
поведение таблицы; смешивать backend- и HTML-код в одном промпте нельзя.

Для добавления нового рабочего листа backend-промпт отдельно требует не забыть
про `NAVIO → Управление листами`. Модель должна провести пользователя через
обновление `APP_CONFIG_.workingSheets`, проверку нативной таблицы и обязательных
заголовков, появление листа в динамическом интерфейсе управления, восстановление
служебной логики, `installProject()` при необходимости и тест включения/паузы на
копии таблицы.

В конце технической справки находится раздел GitHub. Актуальный проект
опубликован в открытом репозитории
[`SteellleR/NAVIO_sheet`](https://github.com/SteellleR/NAVIO_sheet): его можно
клонировать или форкнуть, вести изменения в отдельной ветке и отправлять через
pull request. Рабочий `.clasp.json` с настоящим Script ID в репозиторий не
попадает.

Активный пункт содержания вычисляется по контрольной линии в первой трети окна:
следующий раздел включается только когда его карточка действительно дошла до
этой линии. Один и тот же алгоритм работает в пользовательском и разработческом
режимах. Клик по пункту содержания отменяет стандартный переход браузера и явно
прокручивает модальное окно к нужной секции. Это одинаково работает в обоих
режимах и не зависит от обработки hash-навигации внутри iframe Apps Script.

Служебные столбцы находятся по точным заголовкам, а не по буквам колонок.
Поэтому внутри нативной таблицы можно добавлять новые столбцы и сдвигать
существующие. Нельзя переименовывать или дублировать служебные заголовки,
переносить строку заголовков и выносить служебные столбцы за границы нативной
таблицы.

HTML-документация считается частью проекта. При изменении пользовательского
поведения, архитектуры, scopes, триггеров или процесса публикации нужно в одной
правке обновить и `README.md`, и соответствующий раздел
`DocumentationDialog.html`.

### Почему здесь `.gs`, хотя это JavaScript

Google Apps Script использует JavaScript на V8. Расширение `.gs` - соглашение
самого Apps Script. VS Code понимает эти файлы через настройки `jsconfig.json` и
типы `@types/google-apps-script`.

### Глобальное пространство имён

Apps Script не использует здесь ES-модули `import/export`: все файлы проекта
загружаются в одно глобальное пространство.

Поэтому:

- публичные ручные функции называются без `_`;
- внутренние функции заканчиваются `_`;
- глобальные имена не должны повторяться;
- новые глобальные функции проверяет `check-structure.mjs`;
- общие константы добавляются в `APP_CONFIG_`, а не раскидываются по файлам.

`filePushOrder` в `.clasp.json` держит публикацию предсказуемой, хотя функции
Apps Script доступны между файлами глобально.

## Подготовка `clasp`

### 1. Включить Google Apps Script API

Для аккаунта, который делает `push/pull`, должен быть включён переключатель:

[Google Apps Script API - настройки пользователя](https://script.google.com/home/usersettings)

Это пользовательская настройка. Она не заменяет OAuth-разрешения самого
скрипта.

### 2. Авторизовать `clasp`

Если локальный аккаунт ещё не авторизован:

```bash
npx clasp login
```

Не коммить и никому не отправляй файл с OAuth-токенами `clasp`.

### 3. Создать локальную привязку

```bash
cp .clasp.json.example .clasp.json
```

Потом вставить нужный **Script ID** в `scriptId`.

Для обычной разработки `scriptId` должен указывать на тест. На основу его
меняют только на последнем подтверждённом шаге публикации.

### 4. Проверить цель перед отправкой

```bash
sed -n '1,40p' .clasp.json
npm run status
```

Глазами сверить `scriptId` и список из 17 отслеживаемых файлов.

## Мой безопасный цикл разработки

### Шаг 1. Меняю только локальные файлы

Рабочий код находится в `src`. Не редактирую параллельно ту же функцию в
браузерном редакторе Apps Script, иначе быстро появятся две расходящиеся версии.

### Шаг 2. Добавляю или обновляю тест

Если меняется чистая бизнес-логика, добавляю сценарий в `tests/smoke.mjs`.

Минимум перед публикацией:

```bash
npm run check
```

Все три команды внутри должны завершиться без ошибок.

### Шаг 3. Делаю резервную копию удалённого теста

Самый безопасный способ - клонировать удалённый проект во временную папку **вне
репозитория**. Так `clasp` точно не подхватит родительскую `.clasp.json`:

```bash
mktemp -d -t navio-test-backup
cd ПУТЬ_ИЗ_ПРЕДЫДУЩЕЙ_КОМАНДЫ
npx clasp clone TEST_SCRIPT_ID
```

После успешного клонирования копирую результат в
`backups/YYYYMMDD-test-before-change`.

Папка `backups/` игнорируется Git и не отправляется в Apps Script.

### Шаг 4. Публикую на тест

В `.clasp.json` должен стоять актуальный тестовый Script ID, взятый из настроек
связанного с тестовой таблицей проекта Apps Script.

Проверяю и отправляю:

```bash
npm run status
npm run push
```

`clasp push --force` использую только если обычный `push` ошибочно пишет
`Skipping push`, резервная копия уже есть и цель проверена. Это не штатная
команда на каждый день.

### Шаг 5. Переустанавливаю тестовый проект

После изменения триггеров, интервала, scopes, dropdown-логики или установки:

1. Открываю тестовую таблицу.
2. Перезагружаю страницу.
3. Выбираю `NAVIO → Установить или обновить проект`.
4. Если меню не появилось: `Расширения → Apps Script`.
5. В списке функций выбираю `installProject`.
6. Нажимаю `Выполнить` и подтверждаю разрешения.
7. Жду `Проект установлен и синхронизирован`.

### Шаг 6. Проверяю тестовые сценарии

Не ограничиваюсь фразой «ошибок в журнале нет». Проверяю руками чек-лист из
раздела ниже и смотрю длительности в `Выполнения`.

### Шаг 7. Только после подтверждения иду на основу

Перед основой отдельно сохраняю её текущий Apps Script. Затем меняю `scriptId`
на актуальный основной ID из настроек связанного проекта.

Снова выполняю:

```bash
npm run check
npm run status
npm run push
```

После публикации на основе запускаю `installProject()` уже в основной таблице и
делаю короткую smoke-проверку на реальных данных без разрушительных тестов.

### Шаг 8. Возвращаю локальную привязку на тест

После успешной основной выкладки меняю `.clasp.json` обратно на тестовый Script
ID. Так следующий случайный `npm run push` не полетит сразу в прод.

## Как скачать код из Apps Script обратно

### Вариант A - безопасный, рекомендованный

Если кто-то редактировал код в браузере и нужно посмотреть изменения, я не делаю
`pull` поверх рабочей директории. Вместо этого клонирую проект во временную
папку вне репозитория:

```bash
mktemp -d -t navio-remote-check
cd ПУТЬ_ИЗ_ПРЕДЫДУЩЕЙ_КОМАНДЫ
npx clasp clone SCRIPT_ID
```

Потом сравниваю скачанные файлы с локальными и переношу только понятные
изменения. `clasp clone` может сохранить код как `.js`; для Apps Script это тот
же JavaScript, но в этом репозитории приняты имена `.gs`.

Для теста или основы команда одна и та же, меняется только ID:

```bash
npx clasp clone SCRIPT_ID_ИЗ_НАСТРОЕК_НУЖНОГО_ПРОЕКТА
```

### Вариант B - `pull` прямо в проект

```bash
npm run pull
```

Это быстрее, но опаснее: удалённые файлы могут перезаписать локальные. Перед
таким действием я обязательно:

1. Проверяю `scriptId`.
2. Сохраняю копию `src`.
3. Убеждаюсь, что незакоммиченные изменения не потеряются.
4. После `pull` запускаю `npm run check`.

Если локальная структура `.gs` и удалённая структура `.js` расходятся, лучше не
лечить это принудительным push/pull, а сделать чистый `clone` и осмысленный diff.

## Как сделать резервную копию и откат

### Резервная копия

Копия должна содержать:

- все удалённые `.gs`/`.js` файлы;
- `appsscript.json`;
- `.clasp.json` с Script ID источника;
- понятное имя папки с датой и назначением.

Пример:

```text
backups/20260827-main-before-deploy/
```

### Откат

Откат - это тоже публикация, поэтому порядок такой:

1. Точно определить, какую среду откатываю.
2. Проверить Script ID резервной копии.
3. Сохранить текущую проблемную версию отдельно - она может понадобиться для
   разбора.
4. В чистой папке привязать проверенную резервную копию к нужному Script ID.
5. Выполнить `clasp push`.
6. Если обычный push пропускается из-за локального кеша, только тогда рассмотреть
   `--force`.
7. Запустить `installProject()` и повторить проверку таблицы.

Нельзя брать «похожую» резервную копию теста и без проверки заливать в основу.
Код может выглядеть одинаково, но сначала это нужно доказать сравнением.

## Ручные служебные функции

| Функция | Когда использовать |
| --- | --- |
| `installProject()` | После первой публикации, изменения триггеров, интервала, scopes или конфигурации установки. |
| `removeProjectTriggers()` | Удалить только триггеры этого проекта. Не делает остальную очистку. |
| `syncViolators()` | Принудительный полный пересчёт отчёта. |
| `getLastViolatorsFullSyncMetrics()` | Получить последний сохранённый замер полного прохода. |
| `reconcileLogviewerStatuses()` | Полностью сверить `заполнен` с настоящими `/logs/`. |
| `fillMissingLinks()` | Порциями восстановить служебные ссылки, `заполнен` и даты после удалённых логов. |
| `syncLogCheckDatesFromEvents()` | Заполнить пустые контрольные даты, привести даты к `дд.мм.гггг` и исправить serial numbers. |
| `syncTeleoperatorDropdowns(true)` | Принудительно заменить логины во всех рабочих dropdown. |
| `syncVehicleDropdowns(true)` | Принудительно заменить активные номера ВАТС. |
| `syncLogCheckDateDropdowns()` | Восстановить `Сегодня | заполнен` на ПАО, Такси и Шаттл. |
| `previewVehicleNamesToNumbersMigration()` | Только показать, что будет заменено при миграции ВАТС. Ничего не пишет. |
| `applyVehicleNamesToNumbersMigration()` | Выполнить миграцию после проверки preview. Меняет данные. |

Функции с `_` в конце считаю внутренними. Запускать их вручную без понимания
контекста не надо.

Во время `installProject()` сначала удаляются старые триггеры, затем выполняется
массовая синхронизация и только после неё создаются новые триггеры. Порядок
важен: если поставить `onChange` раньше, изменения нативных таблиц внутри самой
установки могут запустить десятки лишних параллельных обработчиков. Установочный
`onChange` реагирует только на вставку и удаление строк или столбцов; технический
тип `OTHER` намеренно игнорируется.

`reconcileLogviewerStatuses()`, `fillMissingLinks()` и установочная нормализация
дат читают большие рабочие листы порциями по 500 строк. Размер лежит в
`APP_CONFIG_.logviewer.maintenanceChunkRows`. Не стоит сразу увеличивать его до
нескольких тысяч: Google может оборвать единичное чтение Logviewer по таймауту,
особенно при запросе RichText-ссылок.

### Важное про миграцию ВАТС

Всегда сначала:

```javascript
previewVehicleNamesToNumbersMigration()
```

В отчёте могут быть причины:

- `not_found` - название не найдено в справочнике;
- `ambiguous` - одному названию соответствует несколько номеров;
- `formula` - ячейка содержит формулу и не будет перезаписана.

Только после разбора проблем запускать:

```javascript
applyVehicleNamesToNumbersMigration()
```

## Разрешения и манифест

Файл `src/appsscript.json` включает:

- часовой пояс `Europe/Moscow`;
- V8 runtime;
- Stackdriver exception logging;
- расширенный сервис Google Sheets API v4;
- явные OAuth scopes.

### OAuth scopes

```text
https://www.googleapis.com/auth/spreadsheets
https://www.googleapis.com/auth/script.container.ui
https://www.googleapis.com/auth/script.external_request
https://www.googleapis.com/auth/script.scriptapp
```

Для чего они нужны:

| Scope | Причина |
| --- | --- |
| `spreadsheets` | Чтение и изменение таблицы, включая нативные таблицы через Sheets API. |
| `script.container.ui` | Показ меню, модальных окон и HTML-интерфейсов внутри связанной Google-таблицы. Нужен для `NAVIO → Управление листами`. |
| `script.external_request` | `UrlFetchApp` для прямых запросов к Sheets API v4. |
| `script.scriptapp` | Создание и удаление installable-триггеров. |

Scope `spreadsheets` даёт запускающему аккаунту доступ через скрипт ко всем
таблицам, которые доступны этому аккаунту. Сам код работает с текущей связанной
таблицей и сохранённым её ID, но разрешение всё равно широкое из-за используемых
API-возможностей.

После изменения scopes Google может снова попросить авторизацию.

### Блок `webapp`

В манифесте сейчас есть:

```json
"webapp": {
  "access": "ANYONE_ANONYMOUS",
  "executeAs": "USER_DEPLOYING"
}
```

В текущем коде нет `doGet` и `doPost`, а бизнес-логика не использует проект как
веб-приложение. Этот блок унаследован от предыдущей конфигурации развёртывания.
Удалять или менять его можно только отдельной задачей после проверки существующих
deployments. Не надо незаметно смешивать это с обычной правкой логики таблицы.

В исходниках нет паролей, OAuth-токенов или API-ключей. Их там и не должно быть.

| Ресурс | Обычный аккаунт | Google Workspace |
| --- | ---: | ---: |

Дневные квоты считаются на пользователя и восстанавливаются через 24 часа после

Простой `onEdit` должен укладываться примерно в 30 секунд и не может выполнять
действия, требующие отдельной авторизации. Поэтому тяжёлая синхронизация
справочников вынесена в installable-триггеры, а обычный `onEdit` сделан
инкрементальным.

### Квоты Sheets API

Отдельно действуют поминутные лимиты чтения и записи:

| Операция | На проект в минуту | На пользователя в проекте в минуту |
| --- | ---: | ---: |
| Чтение | 300 | 60 |
| Запись | 300 | 60 |

Они пополняются каждую минуту. При превышении обычно приходит HTTP `429`.

Наш полный проход делает один запрос метаданных Sheets API и обычно не пишет
через API, если таблицу `Нарушители` не нужно расширять. Основной расход здесь -
не количество API-запросов, а суммарное время триггеров.

### Практический расчёт для текущего проекта

При полном проходе 26,954 секунды:

| Интервал | Запусков/сутки | Примерное время/сутки |
| --- | ---: | ---: |
| 10 минут | 144 | 64,7 минуты |
| 15 минут | 96 | 43,1 минуты |
| 30 минут | 48 | 21,6 минуты |

К этому добавляются installable `onEdit`, `onChange`, установка и ручные
запуски. Поэтому 10 минут допустимы на текущем размере, но для consumer-аккаунта
запас уже не огромный. Я бы следил за журналом хотя бы после заметного роста
таблиц.

### Признаки упора в квоту

В журнале появляются ошибки вроде:

```text
Service using too much computer time for one day.
Service invoked too many times.
Limit exceeded.
429: Too many requests.
```

Первое действие - не добавлять `sleep`, а посмотреть, какой тип запусков съедает
время. Обычно безопаснее увеличить интервал полного прохода и сохранить
инкрементальную реакцию на ручные правки.

## Диагностика типовых проблем

### Нет меню `NAVIO`

1. Убедиться, что открыта правильная таблица.
2. Полностью перезагрузить вкладку.
3. Проверить, что в удалённом `EntryPoints.gs` есть `onOpen`.
4. Открыть `Расширения → Apps Script`.
5. Запустить `installProject` напрямую.
6. Посмотреть последнее выполнение `onOpen` на ошибку.

### `403 insufficient authentication scopes`

Проверить `oauthScopes` в `appsscript.json`. Для текущего Sheets API нужен
полный:

```text
https://www.googleapis.com/auth/spreadsheets
```

После обновления манифеста снова сделать push и повторно авторизовать
`installProject()`.

Если ошибка появляется при открытии `NAVIO → Управление листами` и упоминает
`Ui.showModalDialog`, в манифесте также должен быть scope:

```text
https://www.googleapis.com/auth/script.container.ui
```

После его добавления нужно снова отправить проект и один раз повторно
авторизовать `installProject()`.

### `Не найден лист`

Проверить точное имя, пробелы и регистр. Основные имена лежат в `Constants.gs`.

### `Не найден столбец`

Код ищет заголовок в строке `1`. Проверить:

- точный текст;
- нет ли второго такого же заголовка;
- не съехала ли строка заголовков;
- не превратился ли лист в обычный диапазон.

### `Нельзя выбрать числовой формат ячеек для столбца с заданным типом данных`

Это особенность новых нативных таблиц Google Sheets с типизированными
столбцами. В актуальной версии поиск заголовков использует `getMaxColumns()`
вместо проблемного `getLastColumn()`, поэтому установка не должна на этом
падать. Если ошибка вернулась, сначала проверить, что в Apps Script опубликована
последняя локальная версия, а затем повторить `installProject()`.

### `Service Spreadsheets timed out` или `failed while accessing document`

Обычно это не повреждение таблицы, а таймаут слишком большого единичного чтения.
Полная сверка Logviewer в актуальной версии разбита на порции по 500 строк. Если
ошибка повторяется даже после обновления кода, можно временно уменьшить
`maintenanceChunkRows`, снова выполнить локальные проверки, опубликовать код и
повторить `installProject()`.

### `Найдено рабочих нативных таблиц: 0` или больше одной

Полный проход ищет ровно одну нативную таблицу с обязательными столбцами на
каждом рабочем листе. Нужно проверить структуру в интерфейсе Google Sheets, а не
просто цвет заголовков.

### На Шаттле осталось `Дата` вместо `Сегодня`

Запустить:

```javascript
syncLogCheckDateDropdowns()
```

Или полный `installProject()`.

### Телеоператор добавляется, но не удаляется

Dropdown должен полностью заменяться через `updateTable`, а не дополняться.
Проверить:

- работает ли installable `handleReferenceSheetsEdit`;
- вызывается ли `syncTeleoperatorDropdowns(true)`;
- доступен ли Sheets API;
- не осталось ли несколько нативных таблиц с одинаковым заголовком.

### `заполнен` не снимается после удаления лога

Проверить, не осталась ли в ячейке скрытая RichText-ссылка. Для массового
восстановления:

```javascript
reconcileLogviewerStatuses()
```

### Вместо даты отображается число вроде `46272`

Это старое календарное значение, у которого Google Sheets потерял формат даты.
Новая версия передаёт контрольные даты локализованным значением `дд.мм.гггг` и
умеет распознавать старые serial numbers. Для массового исправления запустить:

```javascript
syncLogCheckDatesFromEvents()
```

Или полный `installProject()`.

### В заполненной строке нет `Добавить лог`

Сначала проверить, что в строке есть валидная `Дата` и распознаваемый номер
`ВАТС`. Новая версия восстанавливает ссылку при любом следующем ручном изменении
этой строки. Для исправления всех уже накопившихся пропусков запустить:

```javascript
fillMissingLinks()
```

`installProject()` теперь тоже выполняет этот полный восстановительный проход.

### Полный проход стал долгим

1. Сравнить `rowsScanned` с предыдущими логами.
2. Проверить границы нативных таблиц: возможно, они случайно растянуты на тысячи
   пустых строк.
3. Проверить количество параллельных выполнений.
4. Посмотреть, не вызывается ли полный проход из нового `onEdit`.
5. Увеличить интервал до 15 или 30 минут и переустановить триггеры.
6. Не оптимизировать ценой потери обратимости отчёта.

### Таймер пишет `Не сохранён ID связанной таблицы`

Значит не выполнен `installProject()` или очищены Script Properties. Запустить
установку из нужной связанной таблицы.

## Что можно менять относительно спокойно

- URL и подписи Logviewer - через `APP_CONFIG_` и соответствующие тесты.
- Цвета - через `APP_CONFIG_.formatting`.
- Окно 30 дней и порог 4 дня - через `APP_CONFIG_.violators` плюс тесты.
- Интервал полного прохода - через `fullSyncIntervalMinutes` и повторный
  `installProject()`.
- Допустимые заголовки справочника - через `APP_CONFIG_.references`.
- Тексты меню - в `addProjectMenu_()`.

## Что менять только с полноценным тестом

- имена листов;
- заголовки рабочих столбцов;
- имена и расположение нативных таблиц;
- порядок вызовов внутри `onEdit`;
- правила определения настоящей ссылки;
- порог просроченной контрольной даты;
- структуру A:C листа `Нарушители`;
- OAuth scopes;
- имена handler-функций триггеров;
- `webapp` и deployments.

---

## Известные ограничения и технический долг

1. Блок `webapp` в манифесте не используется текущей логикой и требует отдельной
   проверки существующих deployments перед удалением.
2. Smoke-тесты проверяют чистую логику, но не эмулируют Google Sheets API и
   реальные триггеры.
3. Метрика сохраняет только последний успешный полный проход. Историю нужно
   смотреть в `Выполнения` или отдельно выгружать в мониторинг.
4. Интервал 10 минут на consumer-квоте оставляет ограниченный запас. После роста
   данных первым делом смотреть реальные `durationMs`, а не гадать.

## Как я бы принимал проект после передачи

1. Открыл локальную папку в VS Code.
2. Выполнил `npm install` и `npm run check`.
3. Проверил, что `.clasp.json` смотрит на тест.
4. Склонировал тестовый Apps Script в отдельную временную папку и сравнил с
   локальным `src`.
5. Запустил `installProject()` на `Копия V2`.
6. Прошёл тестовый чек-лист выше.
7. Посмотрел хотя бы один полный и один инкрементальный замер.
8. Проверил список триггеров и отсутствие дублей.
9. Только после этого принял бы решение о публикации на основу.

Если придерживаться этого порядка, проект довольно предсказуемый. Главные места,
где можно случайно устроить приключения: неверный Script ID в `.clasp.json`,
сломанная нативная таблица, изменение заголовков без конфигурации и слишком
частый полный триггер. Всё остальное обычно диагностируется журналом и локальными
тестами.
